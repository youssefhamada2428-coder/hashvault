### Documentation
* Business Plan → Our project is HashVault, a Cybersecurity web tool that provides accessible, browser-side cryptographic hashing to verify data integrity without transmitting sensitive payloads. Scope includes hashing files/text and logging history securely.
* Financial Analysis → Built using open-source frameworks (Next.js, Tailwind) and free-tier cloud services (Supabase, Vercel). The initial infrastructure and hosting cost is $0. Operational costs scale predictably with database usage.
* Task Planning → Project timelines, tasks assignments, and sprint simulations are documented. Refer to `documantion/implementation_plan.md` and `documantion/task.md` for sprint tracking.

### Implementation
* CRUD screens → The application has exactly 4 core screens interacting with the database: 1) Text Hashing (Create), 2) File Hashing (Create), 3) Comparison Engine (Create/Read), 4) History Log (Read/Delete).
* Version control → Configuration and code tracking managed via Git/GitHub.
* Requirements mapping → This document and `RUBRIC1_MAPPING.md` trace every grading rubric requirement directly to exact project implementations. 
*  KPIs / Dashboards →  Project KPIs such as task progress, sprint tracking, and workload distribution were managed through structured planning documents rather than being implemented inside the application UI.
This design decision was intentional to:
* Keep the cybersecurity tool focused and lightweight
* Avoid unnecessary UI complexity unrelated to core functionality
* Demonstrate understanding of project management concepts without overengineering the system
Supporting evidence is provided in:
* `documentation/implementation_plan.md`
* `documentation/task.md`
